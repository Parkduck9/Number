# BUG-R4-03 반사탄이 원웨이를 먼저 만나면 같은 이동 구간의 일반 벽도 무시함

- 기준: `25a974e` / 관련: DECISIONS 40의 반사탄 원웨이 통과
- 확인 방법: BoxCast 단일 결과와 분기 분석. 아래 제어된 Play 재현은 실행하지 않음.

## 재현 단계
1. 담당 개발자가 Play 테스트 환경에서, 반사탄의 한 프레임 이동 구간에 원웨이 발판과 일반 Ground 벽이 차례로 걸리는 조건을 만든다. 낮은 프레임률/긴 프레임에서도 확인한다.
2. 최소 배치 예: 탄 중심이 `(0,5)`에서 `(4,5)`로 이동하고, 경로의 x=1에 얇은 원웨이 Collider, x=2에 얇은 일반 벽 Collider가 있다. 둘 다 탄의 높이와 겹치고 프레임 종료 위치는 벽 너머다.
3. 두 번째 Collider에서 탄이 제거되는지 확인한다.

## 기대 결과
원웨이는 통과하지만 그 뒤의 일반 벽에서 제거된다. 프레임이 길어도 전체 이동 구간의 일반 Ground 충돌은 유지된다.

## 실제 결과
한 번의 BoxCast에서 반환한 첫 Collider가 원웨이면 파괴 분기를 통째로 건너뛴다. 같은 구간 뒤쪽의 일반 벽을 다시 검사하지 않는다. 종료 위치가 벽 너머면 다음 프레임의 검사도 이미 벽 뒤에서 시작하므로 통과가 확정된다. 이는 원웨이만 제외해야 하는 변경이 일반 벽 검사까지 누락하는 경우다.

## 심각도
낮음 — 여러 Collider가 한 이동 구간에 걸릴 때의 지형 관통. 특히 긴 WebGL 프레임에서 드러날 수 있으며, 정상 프레임의 모든 반사탄이 관통한다는 뜻은 아니다.

## 코드 근거
- `Assets/Scripts/Combat/EnemyProjectile.cs:87–100`: 이전 위치를 저장하고 탄을 이동한 뒤, 전체 step을 `Physics2D.BoxCast(...).collider` 한 개로 검사.
- `Assets/Scripts/Combat/EnemyProjectile.cs:101–105`: 첫 결과가 `Reflected && wall.usedByEffector`이면 지형 충돌 처리를 끝냄. 이후 Ground 재검사 없음.
- `Assets/Scripts/Player/PlayerController.cs:619–622`: 기존 시선 검사는 결과 배열을 순회하며 effector만 제외하는 구조라 비교 참고 가능.

## 수정 힌트 (Sonnet 구현 → Opus 검수)
재사용 결과 버퍼로 이동 구간의 충돌을 조회하고 반사탄에서 원웨이만 제외한 뒤, 남은 일반 Ground가 있으면 제거한다. 보통 탄은 여전히 지붕 조각에 막혀야 한다. 새 per-frame 배열 할당을 피하고, 버퍼 용량도 점검한다.

수정: EnemyProjectile이 재사용 버퍼(16)로 이동 구간 전체를 BoxCast해 반사탄은 원웨이만 건너뛰고 나머지 Ground 히트가 있으면 제거.
