# BUG-R2-03: "모든 적 처치" 규칙 때문에 세로 맵에서 바닥 적을 놓치면 다시 내려갔다 올라와야 한다 (STG-01/02/04 SEG-B)

## 심각도
**중간** (소프트락은 아님: 위에서 아래로는 떨어질 수 있다. 진행 흐름과 시간 문제)

## 재현 단계
### 경우 1: STG-04 SEG-B (방송 0 = 시민이 굳는 구간)
1. SEG-B 바닥의 시민(E-B1, E-B3, E-B5, E-B6)은 방송 0 때문에 `Frozen`이라 따라오지 않는다. 플레이어는 이들을 무시하고 리프트(x 46~56)를 타고 올라갈 수 있다.
2. 위쪽(고가 달리기 구간)의 적·장치를 모두 처리하고 골(x 72~75, y 11.5)에 들어가면 "적 4 남음"으로 거절된다.
3. 바닥(y 1.0)까지 내려가 굳은 시민을 하나씩 직접 쳐야 하고, 다시 리프트 7칸을 올라와야 한다.

### 경우 2: STG-01 / STG-02 SEG-B
1. 바닥/지붕에서 일부 적을 죽이고 위로 올라간다 (STG-01 E-B1·E-B2·E-B4·E-B3, STG-02 E-B2~E-B5).
2. 이 적들은 SEG-B 스폰 장치의 `watched` 목록에 들어 있어서, 장치가 부서지기 전까지 2.5초마다 바닥에 다시 생긴다. 바닥 적은 위로 올라올 수 없다.
3. 장치를 맨 위에서 부순 뒤에도 바닥에는 부활한 적이 남아 있다 → 다시 내려가 처치 → 다시 올라가야 골을 연다.

## 기대 결과
- 설계 의도: "장치까지 감시하면 두 번째 하강을 강요한다 (Fable 검수)". STG-04 빌더는 이를 피하려고 감시 대상을 높은 곳 적(E-B8, E-B9, E-B7, S-B1)으로 줄였다. 하지만 클리어 규칙이 구간 안 모든 적을 세므로 의도가 반쯤만 지켜진다.

## 실제 결과
- STG-01·02는 감시 대상이 구간 전체라 바닥 적도 되살아난다. STG-04는 바닥 적이 안 되살아나지만 살아 있는 채로 남아 클리어를 막는다.
- 힌트는 개수만 알려 주고 위치를 안 알려 준다 (`"Enemies left: N"`).

## 근거
- `Assets/Scripts/Level/StageClear.cs:174-183` `EnemiesLeft`: 골이 속한 카메라 구간의 x 범위 안 모든 `TestEnemy`(Stunned 제외)를 센다. `Frozen`도 센다. y는 보지 않는다.
- `Assets/Scripts/Enemy/TestEnemy.cs:213`: 방송 0이면 시민·저격이 `Frozen`. `PlayerController.cs:385, 415`: 돌진 대상 탐색은 `Frozen`을 제외 (굳은 적은 제자리 공격으로만 맞는다).
- STG-01/02 빌더: `enemies.Where(e => e.f.seg == Spawner.seg)` → 구간 전체 감시 (`Stg01Builder.cs:151-152`, `Stg02Builder.cs:141-142`). STG-04는 `e.f.y >= 11.5f || id == "E-B8"` 필터 (`Stg04Builder.cs:135-136`).
- 높이 차: STG-04 SEG-B 바닥 1.0 → 골 11.5 (리프트 7칸, 칸당 1.5). STG-01 SEG-B 바닥 1.0 → 골 13.0 (8칸).

## 제안
- (a) STG-01/02도 감시 대상을 "스폰 장치와 같은 높이대 적"으로 제한한다. (b) 힌트에 방향 표시(예: "적 3 남음 ↓")를 넣거나, 남은 적 위에 작은 화살표를 띄운다. (c) STG-04 SEG-B 바닥 시민은 굳어 있어도 클리어 개수에서 제외하는 안은 `[제안]`이므로 사용자 확인 필요.
