# BUG-R2-02: 골 트리거가 "들어가는 순간"에만 클리어 조건을 검사해서, 조건을 채운 뒤 골 안에 서 있어도 열리지 않는다

## 심각도
**중간** (막힌 것처럼 보이지만 골에서 나갔다 다시 들어오면 풀린다)

## 재현 단계
1. STG-02 SEG-B 끝까지 가서 적이 남은 채로 골 구역(x 30~33.5)에 들어간다 → "적 N 남음 / 스폰 장치를 부숴라" 힌트가 뜨고 열리지 않는다.
2. 골 구역 안에 선 채로 남은 적(예: 부활한 E-B9)이나 장치를 처리한다. 장치(x 35.5, 박스 34.7~36.3)는 플레이어 x 32.75~33.95에서도 스윙이 닿으므로 골 구역 안에서 때려 부술 수 있다.
3. 마지막 적/장치를 처리한 뒤에도 아무 일도 일어나지 않는다. 구역 밖으로 나갔다가 다시 들어와야 한다.

## 기대 결과
- 조건이 채워지는 순간 (또는 구역 안에서 주기적으로) 클리어가 다시 평가된다.

## 실제 결과
- `OnTriggerEnter2D`만 쓰고 `OnTriggerStay2D`가 없다. 첫 거절 뒤에는 플레이어가 구역을 벗어났다 다시 들어올 때까지 재평가가 없다. 힌트도 2초 뒤 사라져 "왜 안 열리는지" 알 수 없게 된다.

## 근거
- `Assets/Scripts/Level/LevelTransition.cs:304-311`: `OnTriggerEnter2D` 안에서만 `StageClear.TryClear(transform.position)` 호출. `OnTriggerStay2D` 없음.
- `Assets/Scripts/Level/StageGoal.cs:18`도 같은 구조 (확인: `TryClear`는 이 두 곳에서만 호출).
- 골 구역과 장치의 간격: STG-02 골 `Stg02Builder.cs` GoalB x 30~33.5, 장치 x 35.5 → 골 구역 가장자리에서 1.2u. STG-01(골 70~75 / 장치 66.5)은 3.5u, STG-04(골 72.3~75.3 / 장치 68)는 4.3u라 덜 겹친다.

## 제안
- `OnTriggerStay2D`에서 `busy`가 아니고 거절 상태였다면 0.25초마다 `TryClear` 재평가.
