# 03 — 전략 리뷰: 게임을 더 좋게, 남은 잼을 어떻게 일할까

> 2026-11-08 Claude(Opus) 읽기 전용 리뷰. 코드·씬·에셋·기존 문서는 고치지 않았다. Unity Play는 하지 않았다 (코드·문서 근거).
> 기준: [JAM_RULES.md](../../JAM_RULES.md) 심사 — **테마 ×2**, 디자인 구현, 아트·오디오 통일성, 컨셉·응집력. 동점이면 테마 점수.
> 다른 두 리뷰(버그 목록·남은 작업 로드맵)와 겹치지 않게 "방향·우선순위·일하는 방식"만 다룬다.
> 표기: 비용 = 대략 작업 시간(AI 구현+검수 포함), 추천도 ★1~3.

## 3줄 요약
1. **한 방 처치 이후 일반 적에게 숫자가 거의 의미 없어질 위험이 크다** (플레이어 공격 0.08초 vs 적 첫 타 0.325초 → 먼저 때리면 끝). 테마 ×2 점수의 핵심이 흔들리므로, 숫자가 "피할 수 없는 상황"을 레벨에서 일부러 만들어야 한다.
2. 첫 60초(오프닝 "숨 0번" → 도시가 숨을 멈춤)가 이 게임의 가장 강한 무기다. 소리 끊김·정전·숫자 하나만 빛나는 연출에 시간을 쓰고, 중간보스·AI 벌레 전용 타입·대화 연출(TASK-10)은 자른다.
3. 지금 병목은 코드가 아니라 **사용자 확인(플레이·스프라이트·대사)과 실제 WebGL 빌드**다. 정적 QA를 더 돌리기보다 내일(11/09) 첫 WebGL 빌드 + 사용자 10분 플레이를 매일 고정한다.

## (1) 게임 감각·핵심 루프 (한 방 처치 이후)

### 1-1. 진단: 숫자가 아직 중요한가?
- 코드 근거: 일반 적은 어떤 상태든 한 대에 쓰러진다 ([TestEnemy.cs:409](../../Assets/Scripts/Enemy/TestEnemy.cs#L409)). 플레이어 공격은 0.08초 뒤 판정, 앞쪽 약 1.7u ([PlayerController.cs:24-28](../../Assets/Scripts/Player/PlayerController.cs#L24)), 적 사거리 1.8u·첫 예고 0.325초 ([juice.md](../design/impl/juice.md) 템포 표). 이동 속도도 플레이어 8 vs 적 3.75.
- 결과: **1:1 근접전에서는 달려가서 클릭하면 숫자를 읽을 일이 없다.** 숫자는 "먼저 못 때렸을 때"만 의미가 생긴다.
- 문서도 어긋나 있다: [SUBMISSION_PAGE.md](../SUBMISSION_PAGE.md)·GDD 12장은 아직 "숫자가 0이 되면 반격"(감소 규칙)이라고 쓰지만, GDD 5장은 "숫자는 줄지 않는다 + 한 방 처치"로 바뀌었다. 심사위원은 페이지 설명과 실제 플레이가 다르면 "컨셉 응집력"에서 깎는다.
